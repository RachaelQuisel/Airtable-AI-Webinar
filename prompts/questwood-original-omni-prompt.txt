Interface name: Questwood
Source tables: Case Tasks and Staff
Base: appY3L5TcbLUcie6d

Instructions (prompt): You are a game designer building an interactive task-completion game for paraprofessionals. Create a NEW custom interface with one complete “Questwood” page.

1. AESTHETIC
Create a cozy enchanted woodland: illustrated trees, mushroom cottages, friendly animal companions, parchment mission cards, moss green, warm cream, terracotta, and golden rewards. Completing work makes the player’s garden grow. Use readable typography, charming illustrations, and subtle animation.

2. PLAYERS AND MISSIONS
Use Staff records with {Role} = Paraprofessional as players; display {Staff Name}. Default to all paraprofessional Case Tasks using {Responsible Role}. Include an optional player picker through {Assigned Staff}; do not filter by logged-in user.

Show {Name}, {Application}, {Status}, {Internal Due At}, and {Timing Alert}. Include search, status filters, and expandable {Notes}. Sort incomplete tasks by earliest deadline.

3. REAL TASK CONTROLS
Provide “Start” → In progress, “Complete” → Complete, and “Reopen” → Open. Save to {Status}; synchronize {Done}. On completion, populate {Completed At} if blank. Preserve the timestamp when reopening.

Respect edit permissions, prevent repeated submissions, and show save errors. Celebrations happen only after successful saves.

4. POINT SYSTEM — REQUIRED
Every distinct task currently Complete is worth 25 XP. Split those points equally among its linked paraprofessional staff. Unassigned tasks contribute only to the team total.

Calculate scores from Airtable records, including existing completed tasks. Reopening removes that task’s contribution; recompleting restores it without duplicate points. Scores must survive refresh.

Show XP prominently, each task’s reward, completed-task count, and progress toward the next level. Every 100 XP earns a level and a new garden decoration.

5. LEADERBOARD — REQUIRED
Keep a visible leaderboard beside the missions. Show rank, player name, XP, level, and completed-task count. Equal scores share rank. Highlight the selected player.

Calculate rankings across all eligible tasks, regardless of search or display filters. Update after successful status changes. Do not use Dino Scores.

6. GAME FEEDBACK
After completion, grow a flower, animate earned points toward the scoreboard, and reveal earned decorations. Make locked rewards clickable to explain their XP requirements. Support reduced motion.

7. VALIDATION
Verify completion updates the record, points, garden, and leaderboard; refresh preserves results; reopening reverses points. Include loading, empty, and error states.

Use existing fields only. Don’t invent scores, players, or task data. Flag missing configuration instead of creating substitutes.
