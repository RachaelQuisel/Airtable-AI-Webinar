# Examples — Before / After

Side-by-side refactor on a real wedding seating plan extension.

| File | Description |
|------|-------------|
| `wedding-seating-before.jsx` | A realistic Airtable Omni output — static CSS grid, field names as strings, no drag & drop, no dark mode, no error handling, no permissions |
| `wedding-seating-after.jsx` | The same extension after the `airtable-omni-refiner` skill pass |

## Transformations applied

The `after` version applies these patterns from `../reference/transformations.md`:

1. **T1** — Static grid → trigonometric circular layout (seats placed around each table via `cos/sin`)
2. **T2** — Static seats → HTML5 drag & drop with swap-on-occupied
3. **T3** — Blocking writes → optimistic UI with rollback on error
4. **T4** — Single writes → batched `updateRecordsAsync` for swaps
5. **T6** — VIP badge (absolute positioning + conditional render)
6. **T8** — Error / empty / missing-table states
7. **T9** — Responsive breakpoints (`md:grid-cols-2 lg:grid-cols-3 xl:grid-cols-5`)

Plus all baseline refinements:
- `<Suspense>` boundary at the entry point
- `fields` option on `useRecords` (scoped to the 5 fields actually displayed)
- Field IDs centralized in `FIELD_IDS`
- `getTableByIdIfExists` + null handling
- `?? fallback` on every `getCellValue`
- `React.memo` on the `Seat` component
- `dark:` Tailwind variants throughout

## How to read them

Open both files side-by-side. The `before` file is ~70 lines; the `after` is ~280 lines. The size delta is 80% resiliency and optimistic-UI plumbing, 20% the actual circular layout + drag-and-drop feature.
